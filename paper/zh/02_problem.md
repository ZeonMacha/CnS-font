# 2. 问题定义与数据管线

## 2.1 目标字符集：Tongui-8105

本地化目标是**《通用规范汉字表》**（Tongui-8105，"通用规范汉字表"），由中国国家语言文字工作委员会发布。该表按三个频率层级定义了 8,105 个汉字：

| 层级 | 数量 | 说明 |
|:---|:---:|:---|
| 一级 | 3,500 | 最高频（覆盖约 99% 的印刷文本） |
| 二级 | 3,000 | 次高频 |
| 三级 | 1,605 | 扩展（人名、生僻字） |

源字体 `FOT-SkipPro-B.OTF` 覆盖 URO 区段 `0x4E00–0x9FFF` 内 7,912 个 CJK 码位。目标集与源字体的差集产生两个互不相交的工作队列：

- **缺失（Missing）**：在 Tongui-8105 中存在但源字体中无字形的字符 → 4,101 个目标
- **SC 变体（SC-Variant）**：源字体中存在、但日文字形与简体字形不同的字符 → 1,320 个目标

## 2.2 字形分类管线

在任何神经合成之前，每个 Tongui-8105 字符都要经过一个**五级分类器**（[`variant_classifier.py`](../../src/v3/variant_classifier.py)），被归入六个互斥类别之一：

```
┌─────────────────────────────────────────────────────────────────────┐
│                    Tongui-8105（8,105 字）                          │
├─────────────────────────────────────────────────────────────────────┤
│ 1. HARD_KEEP_12     （12 字）                                       │
│    政策锁定、必须保留原始字形的字符。                                  │
│    与源 OTF 做逐点精确比对验证。                                     │
├─────────────────────────────────────────────────────────────────────┤
│ 2. KEEP_SAME_GID    （1,453 字）                                    │
│    日、简两种字形在 Noto Sans CJK 中共享同一字形 ID。                │
│    无差异 → 保留原始 SkipPro 字形。                                  │
├─────────────────────────────────────────────────────────────────────┤
│ 3. KEEP_V1_V2       （349 字）                                      │
│    日↔简微小差异（如 竖弯钩 ↔ 竖+提、ネ ↔ 礻）。                    │
│    低于替换阈值 → 保留原字形。                                       │
├─────────────────────────────────────────────────────────────────────┤
│ 4. KEEP_ALREADY_SC  （874 字）                                      │
│    SkipPro 字形已经匹配简体字形（经门控验证）。                      │
│    无需重绘。                                                       │
├─────────────────────────────────────────────────────────────────────┤
│ 5. MISSING          （4,101 字）                                    │
│    源字体中无字形 → 完整神经合成（Tier 3）。                         │
├─────────────────────────────────────────────────────────────────────┤
│ 6. SC_VARIANT       （1,320 字）                                    │
│    日文字形与简体字形不同 → 部首替换（Tier 3）。                     │
└─────────────────────────────────────────────────────────────────────┘
```

**v4.4 分发策略**：在纯 v4 模式下（自 `47593f5` 起为默认），`MISSING` 与 `SC_VARIANT` 两类字符**全部路由至 Tier 3**（GlobalGlyphTransformer 全字形 SDF 合成）。旧版 v3 各层（Tier 0a 矢量手术、Tier 0b 局部修复、Tier 1 部件拼接、Tier 2 原子装配）仍可通过 `--use_legacy_v3_tiers` 启用，但默认关闭，以消除掩码边界接缝伪影。

## 2.3 输入表示：四通道"脱皮"编码

神经网络输入的核心设计选择是一个**四通道"脱皮（deskinned）"张量**：从几何中性的参考字体中剥离风格化的笔重信息，只保留结构骨架。

### 参考字体选择

使用 **Noto Sans CJK**（可变字体，`NotoSansCJK-VF.ttc`）作为几何参考，从中提取两个子族：
- `sn_jp`：日语字形变体（`language="ja"`，`ttc_index=0`）
- `sn_sc`：简体字形变体（`language="zh-Hans"`，`ttc_index=2`）

参考字体以 **Sans Light 字重**（`wght=300`）渲染，刻意比目标 SkipPro-B（Bold）更细，以制造一个**风格落差（style gap）**供网络跨越。这种"脱皮"输入阻止网络直接复制参考字体的笔重，迫使它学习 SkipPro-B 特有的笔画加粗、终端张开与弯钩曲率。

> **重要**：v4.x 的训练与推理管线实际使用 `weight=None`（VF 的默认 `wght=100` Thin），风格落差更大。v4.5 路线图（第 8 章）建议显式传入 `--noto_weight 300` 以对齐 Plan 3.0 的设计意图。

### 通道构造

对每个字符，将参考字体的轮廓（三次 Bézier 段列表）以 $2S = 512$ 像素（抗锯齿）光栅化后下采样到 $S = 256$。四个通道为：

**通道 0 — $\phi_{\text{light}}$**：参考字形的归一化 SDF。
$$\phi_{\text{light}}(\mathbf{p}) = \text{clip}\left(\frac{d(\mathbf{p}, \mathcal{C}_{\text{ref}})}{T_{\text{trunc}} \cdot \text{u/px}},\ -1,\ +1\right)$$
其中 $d(\mathbf{p}, \mathcal{C}_{\text{ref}})$ 为带符号欧氏距离（外部为正），$T_{\text{trunc}} = 16$ px。

**通道 1 — $\phi_{\text{skel}}$**：带均匀半宽的骨架距离场。
$$\phi_{\text{skel}}(\mathbf{p}) = \text{clip}\left(\frac{r_u - d(\mathbf{p}, \mathcal{S}_{\text{ref}})}{T_{\text{trunc}} \cdot \text{u/px}},\ -1,\ +1\right)$$
其中 $\mathcal{S}_{\text{ref}}$ 为参考字形的中轴骨架（通过 `skimage.morphology.skeletonize` 计算），$r_u = 40$ UPEM 为均匀半宽参数。该通道**独立于外轮廓**地编码**笔画宽度**。

**通道 2–3 — $(\cos 2\theta, \sin 2\theta)$**：由骨架距离梯度导出的方向场。
$$\nabla d(\mathbf{p}, \mathcal{S}_{\text{ref}}) = (g_x, g_y), \quad \cos 2\theta = \frac{g_y^2 - g_x^2}{g_x^2 + g_y^2} \cdot e^{-d/65}, \quad \sin 2\theta = \frac{-2g_x g_y}{g_x^2 + g_y^2} \cdot e^{-d/65}$$
双角编码使方向场**对 180° 旋转不变**（笔画方向是无向的）。指数衰减 $e^{-d/65}$ 将方向信息局域化在骨架邻域内。

### 训练增强

对输入与目标同时施加在线（on-the-fly）增强：
- **字重抖动**：$\phi_{\text{light}} \leftarrow \text{clip}(\phi_{\text{light}} + \delta_w)$，$\delta_w \sim \mathcal{U}[-0.08, +0.10]$
- **半宽抖动**：$\phi_{\text{skel}} \leftarrow \text{clip}(\phi_{\text{skel}} + (r_u' - r_u)/T_{\text{trunc}})$，$r_u' \sim \mathcal{U}[32, 48]$
- **旋转**：$\theta \sim \mathcal{U}[-2°, +2°]$（50% 概率），对 $\mathbf{x}$ 与 $\mathbf{y}$ 同步施加；方向通道旋转 $2\theta$
- **缩放**：$s \sim \mathcal{U}[0.95, 1.05]$（50% 概率），同步施加

所有增强均使用双线性插值，并显式填充背景（SDF 通道填 $-1.0$，方向通道填 $0.0$）。

## 2.4 目标 SDF 构造

目标 $\mathbf{y}$ 是 **SkipPro-B 原始字形**（对 SC-Variant 字符）或**零填充背景**（对源字体中无 SkipPro 字形的 Missing 字符）的归一化 SDF。对 Missing 字符，目标取 Noto SC 字形的 SDF——网络必须学会从 JP 参考几何出发生成 SC 字形。

目标 SDF 以 $2S = 512$ 分辨率计算以保证亚像素精度，再经双线性滤波下采样到 $S = 256$。

## 2.6 数据血缘与哈希校验

依据工程规范（[`AGENTS.md`](../../AGENTS.md) §4.4），管线中所有产物均携带 SHA-256 指纹：

1. **Tokenizer/ID 表**：`data_v2/ids.txt`（来自 `cjkvi-ids` 的 88,939 行）——每次同步均校验 SHA-256
2. **SDF 缓存**：`datasets/v4_inputs_*.npy` + `v4_targets_*.npy`——缓存文件名带 tag，编码留出集大小与画布尺寸
3. **模型检查点**：`checkpoints/v44_zh_sdf_global.pt`——远程→本地传输时校验 SHA-256
4. **输出 OTF**：每个 `CnS-SkipPro-B-v44-*.otf`——构建完成后校验 SHA-256
5. **字形清单**：`outputs/v44_glyph_manifest.json`（5,421 条）——逐字几何诊断

**产物失效规则**：若参考字体（Noto Sans CJK）或其字重设置发生变化，所有 SDF 缓存必须重新生成。当前缓存文件名 tag（`v4_full_n{holdout}_s{canvas}`）**不**编码字重或字体哈希——这是已知的 v4.5 修复项。
